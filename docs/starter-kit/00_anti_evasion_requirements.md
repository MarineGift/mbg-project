# 00 — 안티-회피 요구사항 (필수 준수)

> **이 문서는 모든 작업 프롬프트(02~06)의 일부입니다. AI는 작업 시작 전에 반드시 이 문서를 정독하고, 산출물 전달 시 모든 항목을 자체 검증해야 합니다.**

## 배경

본 프로젝트는 이전에 3차례에 걸쳐 다양한 AI(GPT-5.5, Claude Sonnet 4.6, Gemini 3.1 Pro, Mixture-of-Agents)에게 동일한 작업 프롬프트를 의뢰했습니다. **모든 시도가 평균 60%만 완성**되었고, 동일한 회피 패턴이 반복되었습니다. 이 문서는 그 패턴을 식별하고 명시적으로 금지합니다.

---

## 절대 금지 사항 (Hard Block)

다음 표현이 산출물에 포함되면 **그 즉시 산출물 전체가 거부**됩니다.

### 1. 반복 회피 표현

❌ "나머지 X개도 동일한 구조로 정의…"
❌ "동일 패턴이므로 생략"
❌ "Buyer 템플릿에서 일부만 교체하면 됨"
❌ "투자사 모듈만 작성, 나머지는 사용자가 복제"
❌ "(필요 시 즉시 제공)"
❌ "(다른 6개 모듈도 동일 구조로 작성 완료)" — 실제로 보여주지 않음
❌ "전체 12개 파일은 zip으로 제공하는 것이 좋습니다"
❌ "지면 관계상 핵심 부분만 발췌"

✅ **올바른 방식**: 요청된 N개 모두 실제 코드로 작성. 길이가 길어지면 응답을 분할(Part 1/2 등)하여 모두 출력.

### 2. 코드 골격 회피

❌ `// DB Insert logic...`
❌ `// TODO: 실제 구현`
❌ `// 에러 처리 추가 필요`
❌ `// (트래킹·재시도 등은 production에서 추가)`
❌ 함수 시그니처만 있고 본문이 없는 코드

✅ **올바른 방식**: 모든 함수에 실제 작동하는 본문, 에러 처리, 재시도 로직, 트랜잭션 처리 포함.

### 3. JSON·SQL 절단

❌ JSON 파일이 마지막 항목 중간에서 잘림 (`"min_confidence": 0.9,` 다음에 끝)
❌ SQL 파일이 `END $$;` 없이 끝남
❌ 배열이 `[...]`로 축약됨
❌ 객체가 `{...}` placeholder로 표시됨

✅ **올바른 방식**: 모든 JSON은 닫히고, 모든 SQL은 완전한 트랜잭션 형태. 응답 길이 한계에 닿으면 다음 응답에서 이어서 작성.

### 4. Few-shot 부족

❌ 모듈당 1개 예시
❌ "예시 1: …" + "(나머지 4개 예시 동일 형식)"
❌ 빈 `examples: []` 배열

✅ **올바른 방식**: 모듈당 최소 5개의 실제 입력→출력 페어. 각 예시는 다른 시나리오를 다뤄야 함.

### 5. 모델명 오류

❌ `claude-3-opus`, `claude-3-haiku` (구버전)
❌ `claude-opus-4-5`, `claude-haiku-4-5` (존재하지 않음)
❌ `Claude-Opus-4` (대소문자 표기 오류)

✅ **올바른 모델명 (2026년 5월 기준)**:
- `claude-opus-4-7` (메인 작성·전략, $15/$75 per 1M tokens)
- `claude-haiku-4-5-20251001` (분류·요약, $0.8/$4 per 1M tokens)
- `claude-sonnet-4-6` (선택, $3/$15 per 1M tokens)

### 6. 시스템 프롬프트와 시드 데이터 불일치

이전 시도에서 분류기 시스템 프롬프트는 `material_request`, `meeting_request` 카테고리를 사용했고, `auto_send_rules` 시드도 같은 명명을 썼습니다. **그러나 마스터 프롬프트 표준은 `information_request`, `meeting_scheduling`** 입니다. 카테고리 명명이 코드 전체에서 일치해야 합니다.

✅ **표준 카테고리 (10개, 변경 금지)**:
```
information_request, meeting_scheduling, simple_acknowledgment,
price_negotiation, contract_terms, rejection, complaint,
introduction, follow_up, other
```

### 7. 트리거·인덱스·RLS 누락

❌ 함수만 정의하고 `CREATE TRIGGER`로 테이블에 연결 안 함
❌ "RLS 활성화"라고 적고 `ALTER TABLE ... ENABLE ROW LEVEL SECURITY` 빠뜨림
❌ `organization_id`에 인덱스 없음 (RLS 성능 치명적)
❌ `set_updated_at()`이 `updated_by` 갱신 안 함

✅ **올바른 방식**:
- 트리거는 함수 정의 + `CREATE TRIGGER` 부착까지 모두 작성
- 모든 RLS 대상 테이블에 명시적 `ALTER TABLE ... ENABLE ROW LEVEL SECURITY`
- `organization_id`, FK 컬럼, 검색 컬럼 모두 인덱스
- `updated_at`과 함께 `updated_by`도 자동 갱신

## 필수 검증 절차

산출물 전달 전, AI는 다음 자체 검증을 실행하고 결과를 보고해야 합니다.

### 검증 1 — 완성도 카운트

요청된 산출물 개수와 실제 작성한 개수를 비교한 표를 응답 끝에 첨부:

```
| 항목 | 요청 | 작성 | 누락 |
|------|------|------|------|
| Reply Drafter (7 모듈 × 3 언어) | 21 | 21 | 0 |
| 분류기 프롬프트 (1 × 3 언어) | 3 | 3 | 0 |
| 모듈 도메인 SQL 파일 | 1 | 1 | 0 |
| ... | ... | ... | ... |
```

누락이 1건이라도 있으면 산출물 거부.

### 검증 2 — 회피 표현 자동 검색

산출물에서 다음 단어가 발견되면 해당 부분 재작성:
- "동일한 구조"
- "동일 패턴"
- "나머지는"
- "필요 시 제공"
- "TODO"
- "지면 관계상"
- "// 실제 구현 추가"

### 검증 3 — 모델명 일관성

산출물 전체에서 다음 grep 결과가 0건이어야 함:
```bash
grep -i "claude-3-opus\|claude-3-haiku\|claude-opus-4-5\|claude-haiku-4-5[^0-9]" output/
```

### 검증 4 — JSON/SQL 문법 유효성

- 모든 JSON 파일은 `jq . file.json` 통과
- 모든 SQL 파일은 PostgreSQL 15 syntax 검증 통과 (`psql --dry-run` 또는 sqlfluff)

### 검증 5 — 카테고리 일관성

분류기 출력 카테고리, `auto_send_rules.classification_category`, Reply Drafter의 risk 처리 카테고리가 모두 위 7번 표준 카테고리만 사용하는지 확인.

## 응답 길이 처리 원칙

산출물이 단일 응답에 들어가지 않을 정도로 클 때:

✅ **올바른 방식**:
- "Part 1/3" 형태로 명확히 표시
- 각 Part 끝에 "다음 응답에서 Part 2 작성 예정. 사용자가 '계속'이라고 응답하면 이어서 진행"
- 모든 Part가 완성된 후에야 검증 표 작성

❌ **금지**:
- 길어진다는 이유로 일부만 작성하고 "나머지 동일 패턴" 처리
- 한 응답에 모든 것을 욱여넣어 잘리게 함
- 압축된 형태(YAML 약식, 인라인 짧은 형태)로 변형

## 우선순위 원칙

요청과 충돌이 있을 때 다음 우선순위:

1. **마스터 시스템 프롬프트(01)의 데이터 모델·명명 규칙** — 변경 불가
2. **본 안티-회피 요구사항(00)** — 모든 작업에 적용
3. **개별 task 프롬프트(02~06)의 세부 요구**
4. **사용자가 채팅 중 추가한 컨텍스트**
5. **AI 자신의 판단** — 위 1~4와 충돌 시 따르지 말고 명시적으로 사용자에게 확인

## 마지막 약속

본 프롬프트를 받은 AI는 다음을 응답 시작 부분에 명시적으로 약속해야 합니다:

> "본 작업의 안티-회피 요구사항(00)을 정독했고, 다음을 약속합니다:
> 1. 요청된 모든 항목을 실제 코드로 작성하며, '동일 패턴' 회피를 사용하지 않습니다.
> 2. 모델명은 claude-opus-4-7 / claude-haiku-4-5-20251001 만 사용합니다.
> 3. 카테고리는 마스터 프롬프트 표준 10개만 사용합니다.
> 4. 산출물 끝에 완성도 카운트 표를 첨부합니다.
> 5. 길이가 길면 'Part X/N' 형식으로 분할하여 모두 출력합니다."

이 약속이 응답 시작에 없으면 사용자는 즉시 작업을 거부하고 다른 AI에 의뢰합니다.
